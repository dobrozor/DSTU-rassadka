# Бронирование мест в зале

Flask + SQLAlchemy (SQLite) + Vanilla JS поверх вашей SVG-схемы.

## Запуск
```bash
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt
flask --app main run --debug          # http://127.0.0.1:5000
pytest -q                            # тесты бэкенда и алгоритма подбора
```
База создаётся сама: `instance/hall.db`. Схемы залов лежат в `data/`, список залов — в `halls.py`;
если поменяете «Схема зала.html» — `python tools/extract_svg.py "Схема зала.html"` (перезапишет `data/hall.svg`).

## Несколько залов
Сейчас зарегистрирован один зал — «Конгресс-холл ДГТУ» (`data/hall.svg`). У каждого **сеанса** свой зал:
он выбирается в окне «Новый сеанс» (блок «Зал» появляется, когда залов больше одного). Всё остальное —
схема, зоны, цены по зонам, автоподбор, статистика, CSV — берётся из зала выбранного сеанса.

**Как добавить зал:**
1. Положите SVG в `data/`, например `data/small_hall.svg`. Формат тот же, что у `hall.svg`: каждое место —
   `<circle data-z="зона" data-r="ряд" data-s="место" data-x="…" data-y="…">`, у зон без рядов `data-r` можно
   пропустить, `viewBox` начинается с `0 0`. Сочетание «зона + ряд + место» в зале не должно повторяться.
2. Добавьте блок `register(...)` в конец `halls.py` (там есть закомментированный пример).
3. `python tools/check_hall.py small_hall` — покажет зоны, число мест и подскажет значения `pitch` и `row_link`
   (шаг между местами и порог «соседних рядов» для автоподбора — у каждой схемы они свои).
4. Перезапустите приложение — зал появится в диалоге сеанса. Старую базу трогать не нужно.

Параметры `register`: `key` (латиницей, хранится в базе), `name`, `svg`, `default_zones` (где подбирать места
по умолчанию), `extra_zones_label` (подпись галочки «подбирать и в остальных зонах»), `zone_bias`
(штраф зоны в автоподборе — меньше значит охотнее), `pitch`, `row_link`.

**Чего нельзя:** удалять из реестра зал, в котором уже есть сеансы, и менять `key`. Если в зале уже есть брони,
нельзя менять в схеме названия зон/ряды/номера мест. Зал у сеанса можно сменить, только пока в нём нет занятых мест.

## Файлы (в порядке разработки)
| Файл | Что внутри |
|---|---|
| `models.py` | Часть 1. Event, ShowSession, Order, SeatBooking, AuditLog; UNIQUE на место в сеансе |
| `autopick.py` | Алгоритм подбора блока (сетка «ряд × колонка», штрафы, разбиение на части) |
| `services.py` | Часть 2а. Калькулятор, статистика, журнал, места, CSV |
| `main.py` | Часть 2б. Маршруты Flask (JSON API) |
| `static/app.js`, `static/style.css`, `templates/index.html` | Часть 3. Фронтенд |
| `halls.py` | Реестр залов: какие есть, какая схема и настройки подбора у каждого |
| `seatmap.py` | Читает места из SVG (зона/ряд/место/координаты) |
| `tools/check_hall.py` | Проверка схемы зала и подсказка параметров автоподбора |

## API
| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/halls` | список залов (зоны, число мест, размеры схемы) |
| GET | `/api/halls/<key>/svg` | схема зала |
| GET/POST | `/api/events` | список / создать мероприятие |
| POST | `/api/events/<id>/sessions` | создать сеанс `{hall?, starts_at, base_price, zone_prices}` (`hall` — ключ зала, по умолчанию первый в реестре) |
| PATCH | `/api/sessions/<id>` | зал (только пока нет занятых мест), дата и цены: `hall`, `starts_at`, `base_price`, `zone_prices`, `row_prices` (суммы заказов пересчитываются) |
| GET | `/api/sessions/<id>/state` | заказы с местами, сводка, журнал |
| GET | `/api/sessions/<id>/audit?limit=&before=` | журнал постранично |
| POST | `/api/sessions/<id>/orders` | создать заказ `{name, comment, status, color, price_override, seats:[{zone,row,seat,is_free}]}` |
| PATCH/DELETE | `/api/orders/<id>` | изменить (в т.ч. `status`: reserved/paid) / удалить |
| POST | `/api/orders/<id>/seats` | `{add, remove, set_free, set_paid}` — состав заказа и бесплатные места |
| POST | `/api/sessions/<id>/autopick` | `{count, zones?, alt?}` → блок мест |
| GET | `/api/orders/<id>/export.csv`, `/api/sessions/<id>/export.csv` | выгрузка для Excel |

Имя оператора передаётся заголовком `X-Operator` (URL-encoded) и попадает в журнал.

### Цена билета
Приоритет (более специфичное перекрывает общее): `base_price` сеанса → `zone_prices`
(цена по зоне) → `row_prices` (цена по диапазону рядов внутри зоны) → `price_override`
заказа. `row_prices` — список `{zone, row_from, row_to, price}`; при пересечении
диапазонов побеждает более раннее правило в списке. Пример:
```json
"row_prices": [
  {"zone": "Партер", "row_from": 1, "row_to": 6, "price": 250},
  {"zone": "Партер", "row_from": 7, "row_to": 10, "price": 500}
]
```
В интерфейсе это кнопка «Цены» → блок «Цена по рядам». У каждого правила можно
выбрать один из 10 цветов подсветки (или «без цвета») — свободные места в этом
диапазоне рядов на схеме слегка окрашиваются выбранным цветом; как только место
попадает в заказ, подсветка ряда уступает место цвету заказа. Палитра отдаётся
клиенту сервером (`GET /api/config`) и проверяется им же при сохранении — так что
менять список цветов нужно только в `services.ROW_COLOR_PALETTE`.

База данных, созданная до появления цен по рядам или выбора зала, обновляется автоматически при
следующем запуске (миграция добавляет недостающие колонки; все прежние сеансы остаются в Конгресс-холле).
